# Below-fold

Write a heading only when it has a **source**. A sibling file is a **pointer**. A practice in the repo with no file is a short inline. Omit the heading when there is no source.

## Development status

Source: version, `CHANGELOG`, description, existing README, or the user's answer. Say whether the project is experimental, maintained, or finished — in those words, not "stable" unless the source says it.

## Local development

Source: setup scripts, `mise`, package-manager install and test commands. Contributor clone-and-run. The user's first success is Getting started, above the fold.

## Contributing

Source: `CONTRIBUTING.md` (pointer) or conventions already in the repo (commit style, review process).

## Code of conduct

Source: `CODE_OF_CONDUCT.md` (pointer). Omit when that file is absent and the user did not supply one.

## Releasing

Source: release workflow, release-please, publish scripts, existing docs. How a version reaches users.

## Observability

Source: dashboards, monitors, error-trackers, log aggregators, or the user's answer. How to see the system in production.

## Security

Source: `SECURITY.md` (pointer). Dependabot or CodeQL, when present, is one line beside that pointer. How to report a vulnerability.

## License

Source: `LICENSE`. Pointer plus the license name. Omit when there is no license file and the user did not name one.
